# WaferCore round-4 verification, 2026-11-13

Stream K fixes K1 through K6. The branch contains only allowed Core, fixture,
local-asset containment, benchmark, and Core architecture changes.

## Changes and integration

- K1: `FileContainment` resolves symlinks and compares components using the
  root volume's case rules. A captured instance retains the original root across
  path changes. Local assets retain their descriptor read and `F_GETPATH` check.
  Preview compositions capture attachment-parent roots and recheck them before
  inlining. Library preservation and preview collection use the same helper.
- K2: syntax rules and presentation runs share `TokenKind`. `WaferLimits`
  owns Core byte budgets, the file-read chunk size, and the scan file-count cap.
  Existing `PreviewComposer` limit properties remain aliases.
- K3: `LibraryFile` retains readable `plainText` and derives `searchableText`.
  Search folds once per candidate file. It does not repeat whitespace collapse,
  because the stored body is already collapsed. Ranking and snippets keep their
  case, accent, substring-count, and Unicode behavior.
- K4: default tests assert 0.3 s for parsing and 0.75 s for rendering 20 passes
  through the four compatibility fixtures. Each assertion uses the median of
  three samples after one warmup. Fixture reads and parse setup for the render
  check are outside the timed regions. Output byte counts confirm completed work.
- K5: store construction never enumerates defaults. Explicit legacy pruning is
  idempotent. Existing age pruning also removes all legacy keys, so
  `AppDelegate.applicationDidFinishLaunching` already performs migration once.
  Each render visitor builds its known-footnote-label set once.
- K6: benchmark runners and reports moved from test fixtures to this directory.
  The build helper now resolves the repository from its new location.

The additive public API consists of:

- `FileContainment.init(rootDirectory:)`, `contains(_:)`, and
  `FileContainment.isContained(_:in:)`.
- `WaferLimits` constants.
- `LibraryFile.init` without the redundant `searchableText:` argument.
- `ScrollStateStore.pruneLegacyEntries()`.

Existing public signatures remain. The original `LibraryFile` initializer now
derives search text from `plainText`; it no longer retains the supplied folded
text. Callers that provide separately authored search text must use readable
body text as the canonical content.

The integrator can replace these app literals without changing values:

| App site | Shared constant |
| --- | --- |
| `MarkdownSourceLoader.maximumSourceByteCount`, 32,000,000 bytes | `WaferLimits.documentSourceByteCount` |
| `LocalAssetLoader.load` default, 25 MiB | `WaferLimits.assetByteCount` |
| `WebKitLocalAssetSchemeHandler.maximumByteCount`, 25 MiB | `WaferLimits.assetByteCount` |
| `RemoteImageSchemeHandler.defaultMaximumByteCount`, 25 MiB | `WaferLimits.assetByteCount` |
| `LocalAssetLoader.read` chunk, 64 KiB | `WaferLimits.fileReadChunkByteCount` |

Current call-site lines are `MarkdownSourceLoader.swift:103`,
`LocalAssetLoader.swift:15`, `WebKitLocalAssetSchemeHandler.swift:21`,
`RemoteImageSchemeHandler.swift:39`, and `LocalAssetLoader.swift:89`.

Those constants remain unchanged in app sources because this stream's app edit
permission covers containment only. The 20 MiB export inlining allowance is an
app-specific policy, not a duplicate Core limit. The editor's 80,000-unit layout
threshold counts UTF-16 units, not bytes. No scroll-store app call change is
required: launch already calls `pruneEntries(olderThan:)`.

## Library footprint and query cost

Retained footprint fell 30.6%, from 137.2 to
95.2 MiB. Full-text query `needle` without snippets rose from
630.9 to 963.1 ms, about 53% slower.
The memory saving is clear. Search recomputes normalized text rather than
retaining a second body, so query CPU cost increases. Scan timing is noisy;
the overlapping ranges do not support a firm scan-speed claim.

Values below are medians with minimum and maximum in parentheses.

| Scan and index, ms | 8927.1 (8557.9 to 9028.2) | 7376.9 (7165.6 to 11035.5) |

The removed body represents about 40 MB of fixture text. The roughly 42 MiB
footprint reduction also includes allocator overhead. No runtime errors or
incorrect scan/query results occurred in the recorded processes.

To reproduce the before build on baseline `0181997`, use its
`Tests/Fixtures/WaferCore/Benchmarks/library-index.py` helper. On this branch:

```sh
python3 docs/benchmarks/library-index.py /tmp/wafer-k-index-final
```

Run the before and final binaries in alternating fresh processes five times.
Each emits one JSON record. `round-4-results.jsonl` retains all ten records.


The method is unchanged from [README.md](README.md): 2,000 actual Markdown
files, exactly 20,000 bytes each, with varied words and an accented header.
Each fresh process measures the increase in
`TASK_VM_INFO.phys_footprint` immediately before and after a retained
`LibraryScanner.scan`, after parse temporaries are released. This counts
allocator pages and metadata as well as text buffers.

Every scan checks 2,000 files, no truncation, no failure, and zero skipped
items. Each of eight query modes checks its expected match count. Snippet
queries also check populated snippets. Fixture generation is outside timing.
This is the complete Core scan and search path, without AppKit presentation.

The baseline uses `0181997` Core sources. Both sides use Swift 6.4.2 release
objects and `swiftc -O -whole-module-optimization` for arm64 macOS 14.
Five fresh processes per side run in strictly alternating order. This Mac has
14 logical CPUs. Background work and concurrent stream builds/tests raised
load averages from about 3 to 14, with later values around 9. Timing ranges
therefore matter. The retained-footprint ranges do not overlap.

A separate, unreported `sample <pid> 3` run found time in Foundation folding,
whitespace replacement, and substring scanning under
`LibrarySearch.fullTextMatches`. The stored body is already whitespace
collapsed. The final computed property therefore omits the redundant regex
pass while preserving the public folded-text result. The profile log is
`/tmp/wafer-k-query-sample.txt`; its process is excluded from measurements.

The initial fold-on-query experiment and a slower direct case-insensitive
range experiment are retained in `round-4-fold-on-query-results.jsonl` and
`round-4-direct-match-results.jsonl`. They are separate from the final five
pairs in `round-4-results.jsonl`.
