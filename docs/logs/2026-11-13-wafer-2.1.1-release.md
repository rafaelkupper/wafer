# Wafer 2.1.1 release, 2026-11-13

Status: complete. Wafer 2.1.1 (build 21) is notarized and published as release `v2.1.1` in the private repository, with the update feed on `main`. Making the repository public is the only remaining step. `OWNER` stands for the GitHub account that hosts the repository.

## Scope and baseline

On 2026-11-13 the user authorized creating the private repository `OWNER/wafer`, pushing the source, building, signing, notarizing, creating the distribution ZIP, and adding the release, so that switching the repository to public is the only remaining step. Deleting the earlier `wafer-releases` repository is not part of this work.

- Previous release: 2.1.0, build 20, published from a separate releases repository with a GitHub Pages feed, under an earlier bundle identifier.
- New manifests (app and Quick Look): 2.1.1, build 21. Both pass `plutil -lint`.
- Release content: the `dev.wafer.app` identity, the AGPL-3.0 license, the new README and documentation, and the update feed moved into the source repository.
- Update feed in `App/Info.plist`: `https://raw.githubusercontent.com/OWNER/wafer/main/appcast.xml`. The public EdDSA key is unchanged; `generate_keys -p` printed the same key from the login Keychain.
- Feed baseline: `appcast.xml` at the repository root with a channel and no items.
- Signing identity: one valid Developer ID Application identity is available.
- Toolchain: Swift 6.4.2.
- Pre-release checks on 2.1.1 (21): `swift test` passed 577 tests with zero failures (core 240, app 337); the release-tool tests passed (3 tests).

## Anomalies

- Notarization was first blocked by Apple with `HTTP status code: 403. A required agreement is missing or has expired.` on three attempts between 11:20 and 11:30 local time. After the account holder accepted the agreement, the same profile answered `HTTP status code: 401. Invalid credentials.` on three attempts: the stored app-specific password was no longer valid. The profile was re-created with `notarytool store-credentials VibeMD` using a new app-specific password supplied by the account holder; the password is stored only in the login Keychain.
- `scripts/release.py` reads the live feed over anonymous HTTPS, which a private repository does not serve. For this first release the feed was read through the authenticated GitHub API by a local wrapper (`.cache/release-private-repo.py`, not tracked). The script itself is unchanged and needs no wrapper once the repository is public.
- The feed commit was made with the repository's contributor identity set through the Git author and committer environment variables, because the publish step commits from a fresh clone.
