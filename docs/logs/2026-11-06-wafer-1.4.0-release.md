- Command: `WAFER_NOTARY_PROFILE=VibeMD scripts/package-release.sh`.

### First packaging attempt: failed before signing

- Tests passed (292, zero failures) and the release app assembled at 1.4.0, build 17.
- `scripts/verify-appex.sh` then failed: "Quick Look extension is missing WaferCore resources". Nothing was Developer ID signed or submitted to Apple.
- Cause: the toolchain moved from Swift 6.3.3 (1.3.0) to Swift 6.4.2. SwiftPM 6.4 emits `Wafer_WaferCore.bundle` in the macOS layout (`Contents/Resources/...`) instead of flat, and the verifier hard-coded flat paths. All files were present.
- Runtime is unaffected: resource lookup uses `Bundle.resourceURL` and `url(forResource:)`, and the test suite already ran against the new `.build` layout.
- Fix: `verify-appex.sh` now resolves `Contents/Resources` when present and otherwise keeps the flat paths. It passed against the assembled build. `ARCHITECTURE.md` notes the layout difference.

### Second packaging attempt

- Same command, rerun after the verifier fix.
- Packaging script completed with exit code 0. Tests passed: 292, zero failures.
- App and Quick Look extension signed with Developer ID, hardened runtime, and secure timestamps. Strict signature and Quick Look verification passed.
