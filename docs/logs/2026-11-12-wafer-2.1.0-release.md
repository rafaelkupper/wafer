# Wafer 2.1.0 release, 2026-11-12

Historical record. Names and local paths have been normalized for publication; repository URLs are examples.

## Scope and baseline

On 2026-11-12 the user asked for auto-update with Sparkle. After the implementation was tested locally, the user authorized two things: creating the public repository `example/wafer-releases`, and releasing 2.1.0 (build 20), meaning the version bump, commit and push to main, notarization, and publication of the ZIP and feed.

- Source baseline: `88d9c92` on main, matching origin/main after a fetch.
- Previous version: 2.0.0, build 19, distributed as a ZIP without an updater. New manifests (app and Quick Look): 2.1.0, build 20. Both pass `plutil -lint`.
- Release content: in-app updates through Sparkle 2.10.1. See `plans/app/2026-11-12/auto-update.md` and `docs/UPDATES.md`.
- Signing identity: one valid Developer ID Application identity is available.
- Toolchain: Swift 6.4.2.
- The VibeMD notarytool keychain profile authenticated successfully (`notarytool history`).
- Sparkle's EdDSA key: `generate_keys -p` printed the public key in `App/Info.plist`.
- Pre-release checks, on 2.0.0 (19) before the bump: `swift test` passed 579 tests with zero failures (core 240, app 339); a signing-only packaging run passed; an update between two throwaway builds installed from a local feed, and a tampered archive was refused. Details are in the plan.
- Left out of the commit: unrelated local changes.

## Execution

- Created `example/wafer-releases`: public, description "Wafer", issues and wiki off, one commit `de26903` ("Wafer", GitHub noreply address) with a one-line README and an empty `appcast.xml`. GitHub Pages enabled on `main`, root, HTTPS enforced. The feed URL answered 200 within two minutes.
- Release source committed as `6156ddc` ("Release Wafer 2.1.0 with in-app updates") on main and pushed to origin (`88d9c92..6156ddc`).
- Command: `scripts/release.py`.
- Preparation completed with exit code 0 on the first attempt. Its own test run passed: 579 tests, zero failures (core 240, app 339).
- Sparkle's four helpers, the framework, the Quick Look extension and the app were signed as Wafer 2.1.0 (20) with Developer ID, hardened runtime, and secure timestamps. Strict signature and Quick Look verification passed.
- Apple notarization: Accepted. Submission ID: `717638b0-981a-4ab0-ab74-a55d4ac1f2c0`. The notary log reports "Ready for distribution" with no issues. Responses: `dist/updates/2.1.0-20/notarytool-submit.json` and `notarization-log.json`.
- The extracted ZIP passed the helper checks (team, timestamp, hardened runtime, no sandbox or debug entitlement), stapler validation and Gatekeeper, extracted with both `ditto` and `unzip`.
- `generate_appcast` wrote one item into the empty feed: title, date, versions, minimum system 14.0, hardware requirement arm64, and the enclosure. `scripts/verify-update.swift` verified the archive length and EdDSA signature against the public key.
- Reviewed `dist/updates/2.1.0-20`, then ran `scripts/release.py --publish dist/updates/2.1.0-20`: exit code 0. It created release `v2.1.0` in `example/wafer-releases` and pushed feed commit `72866d1` (`de26903..72866d1`).
- Output of both runs: `build/release-logs/wafer-2.1.0-prepare.log` and `wafer-2.1.0-publish.log`.

## Verified result

Checked from the public URLs on this Mac, with a browser-style quarantine attribute on the download:

- Release <https://github.com/example/wafer-releases/releases/tag/v2.1.0>: title and notes are each `Wafer 2.1.0`, with one asset, `Wafer-2.1.0.zip`, 10,193,958 bytes. The feed commit message is `Wafer 2.1.0` from the GitHub noreply address.
- Downloaded ZIP SHA-256: `daa6d0e915a0b5ade668100c61468092383975afa3b2b9928dc8e7e05c43797a`, the reviewed value.
- `unzip` and `ditto` each gave no `._` files, a passing `codesign --verify --deep --strict`, a valid stapled ticket, `spctl` accepted as `Notarized Developer ID`, a passing Quick Look verifier, and version 2.1.0 build 20.
- Live feed <https://example.github.io/wafer-releases/appcast.xml> SHA-256: `1a1a916ea4f9708a58c8c7e9cd1986469ec6126f2833388b4fb82acc07f94000`, the reviewed value, about 40 seconds after the push. `scripts/verify-update.swift` verified its signature against the downloaded ZIP.
- The binary was built from commit `6156ddc`. The only differences in the working tree at build time were unrelated local changes and this log, none of which are part of the build.
- The 2.0.0 artifacts in `dist` were not touched: `dist/Wafer-2.0.0.zip` still has SHA-256 `329acdbc812e2f77ac32c794888e0a638479b7052d8d6b213bfc01f2bb6c0f53`.
- `build/Wafer.app` is now the notarized 2.1.0 (20) build.

## What is unverified

- The notarized 2.1.0 app has not been launched. Before the bump, the user clicked through an update of a throwaway ad hoc copy of the same code from a local feed.
- An in-app update from the real feed has not been observed, and cannot be until a build above 20 is published. 2.0.0 has no updater, so its users install 2.1.0 by hand.
- Installing with unsaved edits in an open editor, and the postponed quit when only Sparkle's windows are open.
- Intel Macs: the build is Apple silicon only, as before, and the feed says so.
- Not checked on another Mac and not opened with Archive Utility.
- No Git tag was made in the source repository.
